# widget-trip-agent — Claude Code Context

## What this repo is

An Electron desktop widget (320×240px, always on top, transparent) with a pixel art cat
that reflects the AI agent's work state in real time. Controlled via `paw-plan` CLI over WebSocket.

## Architecture

```
src/main/main.js          Electron main process (CJS) — WebSocket server on :9123, multi-window
src/main/preload.cjs      Context bridge — exposes electronAPI to renderer
src/renderer/app.js       All visual logic — canvas, animations, event handlers
src/renderer/index.html   Widget structure
src/renderer/style.css    Pergamino, footer, progress bar
src/assets/               Spritesheet (pixelart_gato.webp) + tiles
packages/paw-plan/        Standalone CLI — its own git repo + npm package
sprite_scope.html         Standalone spritesheet calibration tool (open in browser)
```

## Critical module system note

**No `"type": "module"` in root package.json.** Electron 33 requires CJS for main process.
`main.js` uses `require()`. `preload.cjs` is explicitly `.cjs` extension.
`packages/paw-plan/` has its own `"type": "module"` — it runs outside Electron.

## Running the widget

```bash
npm install
npm start
```

## Key behaviors

- Windows are created lazily — only on first WebSocket message per `projectId`
- `projectId` = base64 of `process.cwd()`, auto-generated by the CLI
- Multiple repos open simultaneously = multiple cat windows in cascade
- Messages arriving before window loads are buffered in `pendingMessages` map
- Cat auto-sleeps after 2 minutes of silence
- All animations use the "v2" spritesheet positions only (see app.js animations object)
